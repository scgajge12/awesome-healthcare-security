## 基礎ページを置いている理由

[セキュリティの基礎](security-basics.md) は、本リポジトリの各ページが前提として使う語彙と枠組みをまとめたページである。
三省二ガイドライン、FDA と IEC の規格、診断ベンダの提案書は、それぞれ別の枠組みの語彙で書かれる。
同じ「リスク」「脆弱性」「テスト」という語が何を指しているかを突き合わせるために、横断して引く参照材としてここに置いている。

## 倫理のページを置いている理由

[医療の倫理とセキュリティの倫理](ethics.md) は、二つの倫理の概念と考え方の違いを並べたページである。
医療機関で働くセキュリティの担当者は、患者に対する医療者の倫理と、情報を扱う技術者の倫理の間に立つ。
遮断の判断、検証の同意、開示の時期といった場面で、両者は同じ語を使いながら別のことを指す。
特定の工程に属さず各所で引く材料であるため、ここに置いている。

## サービスのカタログを置いている理由

[セキュリティサービスのカタログ](security-services/) は、外部から調達できるサービスを区分ごとに並べたページである。
守る側の人手が足りない以上、実務の相当部分は外部委託になる。
何が売られているかを知らないまま調達仕様を書くと、必要な機能が抜けるか、既に持っている機能を二重に買うことになる。

掲載は推奨ではない。
公開情報で内容を確認できたものを、区分と比較の軸を示すために並べている。
個々のサービスの評価は、自組織の構成に対する提案で行うものだと考えている。

## AI エージェント向けのページを置いている理由

[AI エージェントから使う](ai-agent.md) は、本リポジトリを知識ベースとして読ませる側に向けたページである。
文書はすべて Markdown で公開しているため、取り込むこと自体に手順は要らない。
問題になるのは、要約の過程で一次情報のリンクと「事実」「報道ベース」「分析」の区別が落ちることと、加筆をどう追い続けるかの二つである。
どの群にも属さない使い方の説明であるため、横断して引く参照材としてここに置いている。

## 製薬を独立させている理由

製薬企業のリスクは、治験、製造、供給網という業務の流れに沿って現れる。
システムの種類で切ると、同じ治験データが臨床試験システム、解析環境、委託先の三箇所に分かれて記述が散る。
そのため [技術領域](../technology/) の分類には入れず、業務単位でまとめている。

製造設備の OT は、医療機関側の医療機器と課題が重なる（[医療機器のセキュリティ](../technology/medical-devices/)）。
供給網の論点は、医療機関の委託事業者経由の侵入と同じ構造を持つ（[インシデント事例集](../threats/incidents/)）。
